# План: запись через DIKIDI по прямой ссылке (вариант A) — выполнено

## Цель
Кнопка «Записаться» больше не ведёт на форму с телефоном, а открывает виджет DIKIDI
сразу на шаге «Дата и время» с уже выбранной услугой. Телефон клиент вводит один раз —
в DIKIDI (там он обязателен: авторизация по SMS, обойти нельзя).

## Что выяснено (проверено живьём)
- `dkd.su/1846979` → `https://dikidi.app/1846979`; параметры виджета разбирает сервер,
  формат подтверждён в `newrecord2.js` → `make_url`: `p` (путь шагов), `o` (опция),
  `s` (id услуг через точку), `m` (мастер), `d` (дата-время `YYYYMMDDHHmm`),
  `fn`/`fs`/`fp`/`fc` (имя/фамилия/телефон/комментарий).
- Рабочая ссылка на услугу: `https://dikidi.app/1846979?p=3.pi-po-ssm-sd&o=7&s=<id>`
  — открывается экран «Дата и время» с выбранной услугой и свободными слотами.
  Без услуги: `https://dikidi.app/1846979?p=2.pi-po-ssm&o=7` (выбор услуги).
- Id услуг: `dikidi.app/mobile/ajax/newrecord/company_services/?company=1846979&array=1`
  — 85 услуг, 7 категорий, доступно без авторизации.
- Работает и для услуг с пометкой «Запись через администратора» (проверено на id 22313011).

## Файлы
- `lib/dikidi.js` (Server) — **новый.** Id компании, базовая ссылка, `bookingUrl(dikidiId)`.
- `lib/dikidiServices.json` — **новый.** Карта «наше название услуги → id в DIKIDI»,
  сверенная руками по всем 85 услугам (наши названия в прайсе переписаны короче, чем в
  DIKIDI, автоматическое совпадение даёт только 46/85 — остальное сопоставляю вручную).
- `lib/db.js` (Server) — колонка `price_items.dikidi_id` + миграция `ALTER TABLE` для уже
  существующей базы на сервере + заполнение из карты при сиде и бэкфилле.
- `lib/content.js` (Server) — отдавать `dikidiId` в объекте услуги прайса.
- `components/PriceCard.jsx` (Client) — «Записаться» → ссылка в DIKIDI (`target="_blank"`,
  `rel="noopener noreferrer"`); убрать запись услуги в `sessionStorage` (больше не нужна).
- `components/Hero.jsx`, `components/Header.jsx` (Client) — «Записаться» вместо `#contacts`
  ведёт на базовую ссылку DIKIDI.
- `components/AdminDashboard.jsx` + `app/admin/**` — поле «Id услуги в DIKIDI» у позиции
  прайса, чтобы Екатерина могла поправить/дозаполнить сама.

## Шаги
1. `lib/dikidi.js` + `lib/dikidiServices.json` (ручная сверка 85 услуг).
2. Миграция и бэкфилл `dikidi_id` в `lib/db.js`, отдача поля в `lib/content.js`.
3. `PriceCard` → прямая ссылка; позиции без `dikidi_id` ведут на базовую ссылку DIKIDI.
4. CTA «Записаться» в Hero и Header → базовая ссылка DIKIDI.
5. Поле `dikidi_id` в админке.
6. Проверка: `next build`, прогон по 5-6 ссылкам разных категорий (открывается ли шаг
   «Дата и время» с нужной услугой), десктоп ≥1024px.

## Риски
- Формат `p=3.pi-po-ssm-sd` — внутренний путь шагов DIKIDI, не публичный API: при
  редизайне их виджета может измениться. Ссылка деградирует мягко (открывается виджет
  салона), но проверять раз в пару месяцев стоит.
- Названия в прайсе редактируются в админке → привязка живёт через `dikidi_id` в базе,
  а не через сравнение названий в рантайме.
- Новые услуги, добавленные в DIKIDI, в карту не попадут автоматически — заполняются
  в админке.
